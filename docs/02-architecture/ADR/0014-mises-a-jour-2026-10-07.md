# ADR-0014 — Mises a jour Dependabot #19 du 2026-10-07, dont better-auth 1.7.7 (securite)

- **Statut** : accepte (2026-10-07, claude-code en application de la consigne `docs/04-runbooks/consigne-dependabot-19.md`, accord humain du meme jour ; aucune ligne majeure changee — contestable par l'humain a la revue de la PR)
- **Date** : 2026-10-07
- **Phase** : entretien hors tranche (branche `chore/dependances-2026-10-07`)
- **Decision du registre** : D-051

## Contexte

La PR Dependabot **#19** (« mineures-et-correctifs », 8 paquets) attendait. Deux d'entre eux, `next` et `eslint-config-next` 16.3.8, sont deja dans `main` depuis la PR #21 (commit 24be181, D-047). Les six autres sont des correctifs ou des mineures, dont **`better-auth` 1.7.7, qui corrige des avis de securite** publies le 2026-09-30 : la regle « un correctif de securite prime, dans les 48 h » (`.claude/rules/dependencies.md`) s'applique.

Comme pour ADR-0012, la quarantaine de pnpm (`minimumReleaseAge`) ne doit pas etre contournee : toutes les versions proposees ont ete publiees entre le 2026-09-28 et le 2026-10-01, elles l'ont passee, et `pnpm-workspace.yaml` n'est pas modifie.

## Options envisagees

### Option A — Appliquer les versions de la #19, sans exception a la quarantaine
Ferme la #19 apres fusion, corrige l'avis de `better-auth`, reste dans le perimetre revu par Dependabot.

### Option B — Prendre `latest` du registre du jour
`dotenv` 18.0.6 et `typescript-eslint` 8.71.1 sont sorties depuis. Elles depassent le perimetre de la #19 ; elles arriveront par la prochaine PR hebdomadaire. Ecartee : pas de montee opportuniste.

### Option C — Fusionner la #19 telle quelle
Elle remonte `next` deja a jour et son lockfile date d'avant la PR #21 (overrides `sharp`, `source-map-js`) : conflit et risque de regression. Ecartee.

## Decision

Option A. Versions epinglees exactement, par `pnpm add --save-exact` (racine, `--filter ./apps/web`, `--filter ./packages/db`).

### Avis corriges par better-auth 1.7.7 et exposition reelle de Signet

Les trois avis sont publies dans le depot `better-auth/better-auth` le 2026-09-30 ; ils n'apparaissaient pas encore dans la base globale GitHub lors de la verification.

| Avis | Gravite | Conditions d'exposition (texte de l'avis) | Signet |
|---|---|---|---|
| GHSA-965c-763c-88jm — l'etat OAuth est accepte comme jeton Magic Link (prise de compte) | critique | greffon **Magic Link** actif **et** un fournisseur social ou Generic OAuth **et** etat OAuth en base | **non expose** : aucun greffon (`plugins` absent de `apps/web/src/lib/auth.ts`), aucune occurrence de `magicLink` dans `apps/web/src` ni `packages` (confirme le constat de l'orchestrateur), aucun `socialProviders` |
| GHSA-r4xp-prcw-77qf — OAuth Proxy accepte un profil forge | eleve | greffon **OAuth Proxy** actif, etat en cookie | **non expose** : pas d'OAuth Proxy |
| GHSA-44jh-23m7-hpcf — limiteur de debit depasse par requetes concurrentes | faible | compteurs du limiteur **stockes en base** PostgreSQL via l'adaptateur Drizzle | **non expose** : stockage par defaut en memoire (`buildRateLimitOptions` ne fixe pas `storage`, ADR-0010), adaptateur Kysely interne |

Autre correctif de la version, sans avis : la connexion par ID-token ignorait `disableSignUp` du fournisseur social — sans objet, aucun fournisseur social.

**Exposition reelle : aucune.** Signet n'active qu'email + mot de passe (ADR-0004). La mise a jour est faite quand meme : elle ferme le risque avant qu'un greffon soit active (ex. Magic Link ou connexion sociale dans une tranche future).

## Consequences acceptees

- `dotenv` (18.0.6) et `typescript-eslint` (8.71.1) restent d'un correctif derriere `latest` : la prochaine PR Dependabot les proposera.
- Les liens Magic Link et etats OAuth crees avant la mise a jour deviennent invalides (avis GHSA-965c) : sans effet, Signet n'en emet pas.
- Aucun paquet ajoute ni retire ; `pnpm-workspace.yaml` (overrides, `allowBuilds`) inchange.
- La PR #19 n'est pas fermee a la main : Dependabot la fermera apres la fusion.

## Signal de reexamen

- Activation d'un greffon better-auth (Magic Link, OAuth Proxy, organisation) ou d'un fournisseur social : relire les avis ci-dessus et les options `storeToken`, `storeStateStrategy`, `verification.storeIdentifier`.
- Passage du limiteur de debit en stockage base (multi-instance) : verifier l'atomicite du compteur (GHSA-44jh).
- Un nouvel avis better-auth : regle des 48 h.
