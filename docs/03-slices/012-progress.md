## Blocages
Constat du 2026-10-28 (implementeur), apres 7d5893b. Les pages ont ete verifiees par une sonde jetable hors depot (fetch des memes pages avec `_rsc=`) : vue member sans bloc Palier ni formulaire d'invitation ni cle d'abonnement (HTML et RSC), marqueurs L-8 en place, aucun caractere invisible brut, aucun `__html`, RSC servie en `text/x-component`, liens conformes AC10, message `creation=echec` exact. Les echecs restants viennent des tests, pas des pages ; aucune assertion n'a ete modifiee.
1. **Requete RSC sans `_rsc` (toutes les pages, 71 echecs)** : `getPage(..., { rsc: true })` (`tests/helpers/screens.ts`) envoie `RSC: 1` sans le parametre de cache `_rsc`. Next 16.4.3 a `experimental.validateRSCRequestHeaders: true` par defaut (`next/dist/server/config-shared.js`, l. 265) et repond `307` vers `<chemin>?_rsc` (`base-server.js`, l. 1449 et suivantes, protection contre l'empoisonnement de cache). Preuve : « HTTP 307 recu, 200 attendu. Location : /organisations?creation=echec&_rsc ». Aucune page ne peut l'eviter ; desactiver l'option serait dans `next.config.ts` (hors perimetre) et retirerait une protection. Correction de test : ajouter `_rsc=` (valeur vide quand aucun en-tete de routeur n'est envoye) a l'adresse des requetes RSC.
2. **Statut de la charge RSC d'une page introuvable (AC6, AC7)** : avec `_rsc=`, `notFound()` donne `404` pour le HTML mais `200` pour la charge RSC (Next diffuse la reponse de vol et code l'introuvable dans la charge). `expectFullStatus(page, 404)` exige `404` sur les deux. Correction de test : statut `404` sur le HTML, et pour la RSC une egalite de charge (deja faite par la comparaison normalisee).
3. **Chaine de requete recopiee dans la charge (D-146 point 4)** : Next ecrit la chaine de requete dans les donnees embarquees du HTML et dans la RSC. Extraits : HTML `"c":["","organisations","<id>?role=owner"],"q":"?role=owner"` ; RSC `0:{"q":"?role=owner",...}` ; parametre piege d'AC2 (e) : `"c":["","organisations?creation=PIEGE-ABSENT-x%22%3E%3Cimg+src%3Dx+onerror%3Dalert%2...` (encode, jamais brut) ; RSC `"q":"?creation=PIEGE-ABSENT-x%22%3E%3Cimg%20src%3Dx...`. Touche AC2 (e) (absence du marqueur encode), AC3 (`?userId=` : HTML identique), AC5 (`?role=owner` : identite HTML et RSC) et AC11 (`?token=` : identite, et le jeton passe dans l'adresse figure dans `"c"` et `"q"`). Aucun element reserve a l'owner n'est rendu a un member (verifie). Regle D-146 point 4 : arret, correction par `test-writer`.
4. **Corps du `307` (AC1, 4 echecs)** : `redirect()` renvoie `307` sans donnee, mais le corps HTML porte l'arbre de routage avec les segments du chemin demande (`"k":"<organizationId>"`, `"c":[..., "<id>"]`) ; `expectAbsent` y cherche l'identifiant d'organisation et de collection, que le demandeur a lui-meme fourni. Aucun nom, adresse, titre ni identifiant de lien n'y figure. Correction de test : exclure de la recherche les identifiants presents dans le chemin demande (comme AC6 le fait par remplacement), ou lire seulement `Location`.
5. **`pnpm run check`** : 19 erreurs de lint, toutes dans des fichiers de test de 012 (`tests/helpers/screens-ui.ts` l. 162 `require-await` ; `tests/screens/messages.test.ts` et `form-protection.test.ts` : `unbound-method` sur `chooseMessage` destructure, `ACCOUNT_EXISTS` inutilise). Aucune dans `apps/web/src`.
6. **`pnpm run build` hors environnement de test** : echoue sur `/api/invitations/accept` (route existante, non modifiee) : « DATABASE_URL_AUTH n'est pas definie » a la collecte des donnees de page. ### Implementation (implementeur)
- D-143 (c3deb74) : `minRole: "authenticated"` pour `createOrganization` et `listMyOrganizations`, commentaires alignes sur « toute session valide » ; aucun autre changement du contrat.
- `ui/safe-link.tsx` ne contient que la fonction pure, sans JSX : le test la charge par Vitest, dont la transformation JSX n'est pas configuree a la racine ; le rendu de la ligne de lien est dans un composant serveur separe. Ecarte : un composant JSX dans ce fichier (risque de dependre de la configuration JSX de Vitest, sans gain).
- `ui/messages.ts` recopie les textes de `lib/errors.ts` et des constantes des routes (contrat : « recopies ») au lieu de les importer : le module est charge par des composants clients et reste sans dependance serveur ; le test compare a `lib/errors.ts`, ce qui detecte toute derive. Ecarte : import de `lib/errors.ts` (couplage d'un module client a `lib/`).
- Inscription : « compte existant » = codes better-auth `USER_ALREADY_EXISTS` et `USER_ALREADY_EXISTS_USE_ANOTHER_EMAIL` (`@better-auth/core`, `error/codes`), sur `400`/`422` ; autre `400`/`422` : texte d'adresse ou de mot de passe invalide ; tout autre statut : texte generique. Ecarte : tout 4xx comme refus de saisie (un `418` ou `403` inattendu serait mal explique).
- Formulaires prives : le `422` de « Nouvelle collection » donne toujours le texte du nom invalide (l'identifiant d'organisation vient de la page, jamais saisi) ; `404 ORGANIZATION_NOT_FOUND` et `401` traites avant les codes propres au formulaire.
- `FIXED_MESSAGES` contient aussi les deux textes fixes de page « Lien d'invitation incomplet » et « Votre compte est cree, mais l'organisation n'a pas pu l'etre. Creez-la ci-dessous. » : liste unique de tous les textes affichables, comme le demande la signature.
- `signUpWithOrganization` : l'identifiant rendu par la creation n'est repris dans la destination que s'il a la forme d'un UUID (sinon : `creation_failed`) ; aucune valeur de reponse non verifiee dans une adresse. Erreur reseau = statut 0 (jamais d'exception vers le formulaire).
- Pages (7d5893b) : lecture de session dans `ui/session.ts` (`readPageSession`, `requirePageSession` : `redirect("/connexion")` avant toute lecture) ; identifiants du chemin valides par les schemas des contrats `listMembers` et `listLinks` (re-exportes par `lib/`), puis minuscules ; tout refus de lecture (`ORGANIZATION_NOT_FOUND`, `COLLECTION_NOT_FOUND`) ou ligne absente -> `notFound()` (page introuvable unique) ; `getSubscription` appele seulement si la ligne de l'appelant dans `listMembers` est `owner` ; refus inattendu d'une lecture (`getSubscription` d'un owner, `listMyOrganizations`) -> `throw`, page d'erreur generique `app/error.tsx` (texte fixe, aucun detail).
- Page d'acceptation : l'adresse du compte connecte est rendue par le composant serveur, et le composant client ne recoit qu'un booleen (`signedIn`) ; plus strict que l'exception bornee du contrat (aucun texte libre en props). Jeton lu par `useSyncExternalStore` sur `location.hash` (instantane serveur `null` : rien n'est affiche avant lecture), bouton « Accepter l'invitation » seulement si un jeton est lu ; « Lien d'invitation incomplet » si le fragment est lu sans jeton ; formulaires incorpores toujours servis sans session. Ecarte : `useEffect` + `setState` (regle de lint React 19 et double rendu).
- Suites apres erreur (D-147) : « Se deconnecter » toujours present avec session sur la page d'acceptation (couvre le `403`) ; lien `/organisations` affiche apres `409 ALREADY_MEMBER` ; `401` : « Session expiree. » et lien `/connexion` sur les formulaires prives, relecture de la page (retour aux formulaires incorpores) sur la page d'acceptation.
- Liens internes par `next/link` (regle de lint `no-html-link-for-pages`) ; liens externes `<a target="_blank" rel="noopener noreferrer">` dans `ui/link-row.tsx` (composant serveur : titre et URL bruts ne sont jamais serialises en props).
- Texte de succes ajoute a `MESSAGES` : « Invitation enregistree : l'e-mail part dans quelques instants. » (seule ecriture qui n'a rien a relire a l'ecran ; la liste fermee reste unique). Ecarte : aucun retour apres invitation (l'utilisateur ne saurait pas si l'envoi a eu lieu).
- Apparence : `app/globals.css` minimal, aucune bibliotheque de style (consigne point 10).
- Aucune dependance, aucune migration, aucune variable d'environnement, aucun fichier de `app/api/`, `lib/`, `packages/` modifie (AC15, a verifier par la fiche de preuves).
